# 04 — Reusable Product Patterns

## Dashboard

- Page title + range/filter.
- 2–4 KPIs relevantes.
- Um ou dois gráficos com finalidade real.
- Lista operacional abaixo.
- Evitar mosaico de 12 cards sem hierarquia.

## List / Index

Anatomia:
1. title + description;
2. primary CTA;
3. tabs/views;
4. search + filters;
5. bulk actions quando aplicável;
6. table/list;
7. pagination.

## List + Detail

Desktop: lista e detail/inspector simultâneos quando ganho operacional for alto.
Mobile: navegação list → detail.

## CRUD Form

- Sections explícitas.
- Labels consistentes.
- Action bar previsível.
- Autosave quando contexto suportar.
- Erros inline.
- Confirmar apenas operações destrutivas ou irreversíveis.

## Settings

- Section navigation lateral ou breadcrumbs.
- Groups por domínio.
- Rows compactas.
- Security e permissions com status semântico.

## Billing / Upgrade

- Plano atual inequívoco.
- Opções comparáveis.
- Resumo financeiro persistente quando necessário.
- Não ocultar total/recorrência.

## Onboarding

- Stepper discreto.
- Um objetivo por etapa.
- Skip somente quando permitido.
- Preview útil quando configuração altera aparência.

## Editor

- Canvas dominante.
- Chrome reduzido durante escrita.
- Tools aparecem por contexto.
- Inspector guarda metadata e ações documentais.

## Search + Filters

- Search perto do conjunto que filtra.
- Filtros ativos visíveis/removíveis.
- Saved views somente se houver necessidade real.

## Activity / Audit

- Timeline/lista densa.
- ator + ação + objeto + timestamp.
- filtros por evento/usuário/período.
- detalhes expandíveis.

## Empty states

- Explicar o estado.
- Oferecer próximo passo.
- Evitar ilustrações grandes quando uma ação simples resolve.
